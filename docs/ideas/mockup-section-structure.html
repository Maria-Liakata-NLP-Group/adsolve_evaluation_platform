How should the reframed section be structured?

The current "Evaluation Script Builder" becomes a broader section. How do Library and Builder relate?

A

Sub-navigation tabs

The section gets two tabs: Library (browse aspects & metrics) and Build (the existing wizard). Users land on Library by default.

B

Library + Use Case Paths as two sibling views

Rename the section to "Aspects & Metrics" with two sub-pages at the same level: Library and Use Case Paths (replacing the wizard). No tabs — just two navigation entries.

App header nav
Use Cases Intrinsic Metrics Aspects & Metrics ▾
Library Use Case Paths

Pros

  • Rename signals new purpose
  • Paths feel like one output of the library

Cons

  • Header nav gets a dropdown
  • More restructuring of existing routes
C

Library-first, builder as a panel within it

The Library is the primary view. When an admin wants to create a new path, a side panel or modal wizard opens within the library — building a path means picking aspects/metrics from the library you're already browsing.
