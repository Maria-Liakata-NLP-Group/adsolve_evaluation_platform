One unified section — two lenses on the same data

The library and builder are both about exploring aspects & metrics. How should a user switch between lenses?

A

Two tabs on one page

One section, one route. A tab switcher at the top lets you toggle between Library (aspect/metric-first) and By Use Case (path-first). State persists as you switch — selecting an aspect in the library could highlight it in the builder view.

B

Library IS the section, builder is a path within it ✓ Chosen direction

The section is called "Evaluation" (or "Aspects & Metrics"). The library is the default landing. The current builder wizard is accessible via a "Build by Use Case" button/link — a contextual path rather than a peer tab.

C

Keep two separate home page CTAs, but link them

The home page retains "Explore Use Cases" and "Evaluation Builder" as CTAs, and adds a third: "Aspects & Metrics" (the new library). They're separate pages but cross-link — e.g. a metric in the library links to the paths it's part of, and the builder links to the library for context.
